# Abstract

Deep-search agents answer hard questions by searching a corpus many times and reasoning over what they find; a single vector search or retrieval-augmented generation step rarely suffices, because the evidence is spread over documents that no one query returns. In the standard design every search result is appended to the prompt, so the agent either sees only a fragment of each document or reasons over an ever-growing prompt. We propose an architecture that moves retrieved text out of the prompt and into the program. Whole documents are held as variables in a Python read-eval-print loop (REPL), the model reads them by writing code, and only what the code prints enters its context. The REPL itself is not new: we reuse it from recursive language models and agents such as Agentica. A search cap, not the context window, bounds how much the agent retrieves, so it can fetch whole documents and search wide. We compare the architecture with the benchmark's function-calling agent and variants of it that tackle the same trade-off inside the prompt, with one model for every agent, and ablate its components one at a time. On BrowseComp-Plus questions held out from development it answers 87% versus 78% both for the function-calling agent with a whole-document tool and for Fetch-then-Explore, a recent agent that keeps fetched documents in a workspace, with about a quarter of Fetch-then-Explore's tokens; on the development questions it also uses about a quarter of the function-calling agent's tokens per question. The ablations show where the gain comes from: wide searches find the evidence, and keeping documents out of the prompt is what makes such searches affordable. It also leads on FRAMES and runs with an open-weight model.
