As a general strategy, work out how the query problem would be SOLVED before you search. Relevance is a shared proof strategy - the same abstract meta-move - not a shared topic, so a problem can match while sharing none of its words or its field, and a problem from the same field with similar notation can match nothing. Name the key insight that unlocks the query problem, then search for it from several directions: the meta-move stated abstractly, and concrete problems from other fields that the same move would solve. The index is a dense semantic retriever: it matches meaning, not literal strings, and quotation marks have NO effect. Each hop, search a DIFFERENT angle rather than rewording the last one. You are not looking for one answer: you are building an ORDERED LIST, scored by NDCG@10, so keep every plausible candidate and spend your effort deciding, for each, whether its likely proof really uses the same insight.
